# Independent review — PR #18 (feat/10of10-d3)

**Diff reviewed:** `origin/main..HEAD` (D3 continuous red-team hunt: runner, pure metrics module,
dashboard, CI workflow).

**Method:** the same multi-agent, different-model adversarial workflow used on PR #17. Four reviewers
(Sonnet, `effort: high`), one per lens — metrics-math, runner, ci-workflow, honesty/tests — grounded
in the real `git diff`. Every major+ finding independently verified by two skeptics on **different
models** (Haiku + Sonnet), each told to REFUTE by default and reproduce against the actual code.

**Outcome:** `mergeable: false` on first pass — **9 confirmed major+ findings, 0 dismissed** (all
reproduced live). This is the gate working: it caught the code's central weakness before merge.

## Findings and resolutions

1,2,3,7. **The D3 gate was report-only; CI used an ephemeral series.** `d3Verdict` (the pass/fail
   logic) was called *only* inside `renderDashboard` (an informational artifact) and the tests —
   never anywhere CI branches on. `run.mjs`'s only CI exit-code logic was the current round's
   slips/overblocks; a regression in the rolling-series properties (corpus shrink, rising discovery
   slope, MTTC=∞) would merge freely. And the workflow ran the hunt against a fresh
   `$RUNNER_TEMP/runs.jsonl`, so it always saw `run:1` while its header comment claimed the series
   "accrues over runs." *Fixed:* added `d3Regressions()` (the CI-enforceable subset — reds on real
   regressions but NOT the benign "still accruing <8 runs" state) + a `src/redteam-check.ts` CLI
   wired as a **real** `redteam.yml` gate over the COMMITTED `runs.jsonl`; the workflow now runs a
   detection round AND the series gate, with an honest header (accrual is the still-open D3c task).
   Proof: fault-injecting a regressed series → `redteam-check` exits 1 listing all three violations.

4. **`RunRecord.generated` undercounted the tested population** (seeds×n, excluding the corpus).
   *Fixed:* added an explicit `evaluated` field (= generated + corpus = total run through the guard).

5. **Run-index counted malformed lines.** A truncated last line from a crashed prior run was counted
   as a valid run. *Fixed:* count only lines that parse to a record with a numeric `run`.

6. **`build:cli` in the dashboard step wasn't guarded** — only the final command had `|| true`, but
   Actions' default `bash -e` meant a TS compile error there would fail the (meant-to-be-nonfatal)
   step. *Fixed:* `continue-on-error: true` on the dashboard step; `build:cli` is now its own step.

8. **A vacuous test.** Every fixture had `generated == caught+slips+overblocks`, so a `catchRate` bug
   using `generated` as denominator would still pass. *Fixed:* fixtures now set `generated ≠ evaluated`
   and a leak case pins `190/200 = 0.95` (a generated denominator would give ≈3.17); added
   `d3Regressions` tests (t-m9).

9. **Fabricated committed run rows.** The 3 committed rows had hand-authored timestamps/seeds that
   read like real nightly runs. *Fixed:* regenerated as genuine local runs (real timestamps,
   `source: "local"`), so provenance is explicit and honest.

Minor: `--n` had no NaN/validation → now rejects non-positive/non-integer `--n` and non-numeric seeds.
