# PR #25 — Mutation-testing gate: independent review

**Scope:** `origin/main..feat/reliability-mutation-gate` — the AST mutation tester
(`bench/mutation/mutate.mjs` + `run.mjs`), its docs (`docs/MUTATION.md`), the dedicated CI job, and
the test-hardening that raised the mutation score.

**Reviewer:** independent workflow review by a **different model** (Claude Sonnet 5) — reviewers-by-lens
plus adversarial verifiers over the diff, with each claim reproduced by direct execution
(`pnpm run mutation` run twice; per-mutant hand-application; AST site enumeration).

## What the review confirmed sound
- Mutation score reproduces deterministically; `report.md` matches a fresh regeneration byte-for-byte.
- The mutator only touches real operator/literal tokens (never strings/comments), verified via AST
  site enumeration; the baseline-must-pass guard correctly excludes a module whose unmutated tests fail.
- `version.ts:28` is a genuine equivalent mutant (exhaustively verified under the `!==` guard).
- The sampled hardening tests are non-vacuous (each fails exactly when its target mutation is applied).

## Findings and resolutions
The review returned **NEEDS-FIX**. All six findings are resolved (see `pr-25.findings.json`):

1. **[blocker] False "equivalent mutant" claims for `study.ts`.** The docs excused the
   `twoProportionP`/`normalCdf`/`ci()` survivors as equivalent; they were **real test-quality gaps**
   (loose `< 0.001` / `=== 1` thresholds; untested render scaling). *Fixed:* pinned `twoProportionP`
   to reference p-values from the externally-validated Abramowitz-Stegun CDF (`t-st8`), pinned the
   reachable **α=0.05 boundary** `twoProportionP(13,65,23,65) === 0.05` and the strict `<` E3
   thresholds and the `×100` render (`t-st9`). `docs/MUTATION.md` carries an explicit retraction of
   the earlier false claim — "a mutator that lies is worse than none."

2. **[major] 18 undocumented `redteam-metrics.ts` survivors.** *Fixed:* enumerated all mutation sites
   (no sampling); killed the 9 real gaps (`t-m13`, `t-m14`: the `overblocks` term, the
   `corpusGrowth`/`discoverySlope` length guards, `summarize`'s rounding, and every `d3Verdict`
   reason-text check decoupled from the pass boolean). The residual 5 are each **proven equivalent**
   (guarded loop bounds; `Σ(x−x̄)=0`; always-defined ternary operands; pass-boolean forced to slope 0)
   and listed with justifications in `docs/MUTATION.md`.

3. **[major] Timeout conflated with "killed".** A hang (`status !== 0` from a timeout kill) was scored
   as a caught bug. *Fixed:* `mutate.mjs` detects `ETIMEDOUT`, reports timeouts as a distinct
   **inconclusive** class, and never counts them as killed — a hang can only lower the score, never
   inflate it. (Not exploitable on today's 6 files, but fixed before the gate is ever extended.)

4. **[minor] Silent under-sampling.** The old stride kept fewer than `maxMutants` and disclosed
   nothing. *Fixed:* even-spaced cap that reaches `maxMutants`, `sampledFrom` disclosure in the report,
   and the cap raised to 400 so all modules enumerate fully today.

5. **[minor] CI mutation job had no `timeout-minutes`.** *Fixed:* `timeout-minutes: 20` added.

6. **[minor] Imprecise wording** ("killed 18 more classes"). *Fixed:* `tasks.md` states
   **79.3% → 97.0% (229/236 killed)** accurately.
